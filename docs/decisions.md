### 1. 라이선스

- **그리운 고씨네** — 임베딩 "사용 가능" 명시. 문제 없음. 저작권자 고동성 X 그리운.
- **빛의계승자체** — 임베딩 "조건부 허용". 라이선스 원문의 금지 항목은
  ① 유료 판매 ② 수정·편집·재배포 ③ **게임** 임베딩 세 가지뿐이고 웹 임베딩은 없음.
  원본 OTF를 수정 없이 그대로 서빙하므로 ②에도 해당하지 않음.
  저작권자(컴투스 1588-7155) 확인은 하지 않기로 함.

> 주의: 이 폰트는 **상업적 사용 자체가 무료로 허용**됨. "비상업이라 괜찮다"는
> 판단 근거가 아니며, 조건은 상업성과 무관하게 동일하게 적용됨.

**눈누가 호스팅하는 변환본 `.woff`는 쓰지 않음.** 전송량이 우리 OTF의 gzip 결과와
바이트 단위로 동일(573KB)해서 이득이 0인데, 제3자 변환본 재배포 사슬에 올라타는
리스크만 생김. 두 폰트 모두 **서브셋·포맷 변환 금지**(수정·개작 조항).

## 응원 게시판 설계 트레이드오프

시안에 확정된 것: 입력 폼(`이름` + `메시지`), 쪽지 카드 `428×224`,
테이프 `77×36`을 **8° / −8° 교대**, 악보 배경은 정사각형·직사각형 교대,
쪽지 안 배치는 좌상단 이름 / 가운데 내용 / 좌하단 메시지 아이콘 / 우하단 날짜 (코멘트 #43).

### C-1. 작성자 본인의 수정·삭제

| | 비밀번호 방식 | 브라우저 토큰 | 없음 (어드민만) |
|---|---|---|---|
| 작성 마찰 | 입력칸 +1 | 없음 | 없음 |
| 기기 변경 후 | 가능 | 불가 | — |
| 브라우저 데이터 삭제 후 | 영향 없음 | 권한 상실 | — |
| 구현량 | 중 (해시·검증 UI) | 소 | 없음 |
| 보안 | 짧은 비번 무차별 대입 → rate limit 필수 | 토큰 유출 위험(낮음) | 최고 |
| 저장하는 개인정보 | 비번 해시 추가 | 토큰만 | 최소 |
| 시안 부합 | 시안에 UI 없음 → 추가 필요 | 시안에 UI 없음 → 추가 필요 | **시안 그대로** |

**권장: 없음 (어드민만).** 시안에 수정·삭제 버튼이 아예 없고, 응원 메시지는 짧은
일회성 글이라 수정 수요가 낮음. 공연 기간 한정 사이트에 운영·보안 부담을 늘릴 이유가 약함.
나중에 필요해지면 마찰이 0인 **브라우저 토큰** 방식을 추가하는 것이 쉬움.

### C-2. 대댓글

**결정된 방향**: 쪽지의 메모 아이콘을 클릭하면 이미지 레이어가 늘어나면서 대댓글 표시.

**누가 다는가**

| | 운영진만 | 누구나 |
|---|---|---|
| 스팸 표면 | 없음 | 2배 |
| 모더레이션 부담 | 없음 | 2배 |
| 성격 | 응원에 대한 감사 답글 | 대화·커뮤니티 |
| 봇 대응 | 불필요 | 본문과 동일하게 필요 |

**권장: 운영진만.** 응원 게시판은 방명록 성격이지 커뮤니티가 아님.
제작팀이 응원에 답하는 그림이 이 사이트에 더 맞고, 공개 쓰기 엔드포인트가
하나 더 늘어나는 것을 피할 수 있음.

**데이터 구조**

| | `reply` 컬럼 (1:1) | `guestbook_replies` 테이블 (1:N) |
|---|---|---|
| 구현량 | 최소 | 소 |
| 답글 개수 | 1개 | 여러 개 |
| 나중에 확장 | 마이그레이션 필요 | 불필요 |

**권장: 1:N 테이블.** 지금 비용 차이가 작고, 나중에 "누구나 답글"로 열거나
답글이 2개 이상 필요해질 때 마이그레이션을 피할 수 있음.

**"이미지 레이어가 늘어나는" 확장 연출**

쪽지 배경이 `찢어진악보_Ver3` 비트맵(428×216)이라 높이를 늘리는 방식이 문제가 됨.

| 방법 | 구현 | 왜곡 | 디자이너 추가 작업 |
|---|---|---|---|
| **CSS 세로 늘림** (`background-size: 100% 100%`) | 즉시 | **큼** — 찢어진 가장자리와 악보 오선이 늘어나 티가 남 | 없음 |
| **9-slice** (`border-image`) — 이미지를 상/중/하로 자르고 중간만 반복 | 중 | 없음 | 이미지 3분할 필요 |
| **답글용 작은 쪽지를 아래에 겹쳐 붙이기** | 소 | 없음 | 작은 쪽지 이미지 1종 |
| **모달·팝오버로 확대** | 소 | 없음 | 없음 (단 "늘어나는" 느낌은 아님) |

**권장: 답글 쪽지 겹치기 또는 9-slice.** CSS 세로 늘림은 악보 오선 간격이
벌어져서 눈에 띄게 어색해짐. 겹치기 방식은 "악보 위에 작성되는 느낌"(코멘트 #35)과도 어울림.
→ **디자이너에게 요청 필요**: 9-slice용 3분할 이미지 또는 답글용 작은 쪽지 이미지.

### C-3. 하트

| | 운영진 하트 | 방문자 하트 |
|---|---|---|
| 데이터 | `boolean` 컬럼 1개 | 카운트 + 중복 방지 테이블 |
| 중복 방지 | 불필요 | IP 해시 + localStorage (정확도 낮음) |
| 어뷰징 표면 | 없음 | 있음 (봇 카운트 조작) |
| 의미 | 제작팀이 응원에 감사 표시 | 방문자 간 공감 |

**권장: 운영진 하트.** "우리 하트"라는 표현과도 맞고, `boolean` 컬럼 하나로 끝남.
방문자 하트는 중복 방지를 제대로 하기 어려워 숫자의 신뢰도가 낮고 어뷰징 표면만 늘어남.

> 확인 필요: "우리 하트"가 **제작팀이 누르는 하트**를 뜻하는 게 맞는지.
> 방문자 좋아요를 의도하셨다면 위 표의 오른쪽 열로 진행.

### C-4. 봇 대응

| 방법 | 구현 | 사용자 마찰 | 막는 대상 | 오탐 위험 |
|---|---|---|---|---|
| **Rate limit** (IP 해시) | 소 | 없음 | 대량 등록 | **있음** — 아래 참고 |
| **Honeypot** (숨은 입력칸) | 매우 소 | 없음 | 범용 스팸봇 대부분 | 자동완성 오탐 → `autocomplete="off"` 필요 |
| **제출 시간 검사** (3초 미만 차단) | 매우 소 | 없음 | 자동 제출 | 거의 없음 |
| **링크 포함 글 보류** | 소 | 링크 쓰는 사람만 | 스팸 대부분 | 정상 사용자가 인스타 링크 남길 수 있음 → 삭제 말고 **보류** |
| Turnstile / reCAPTCHA | 중 | 낮음 | 정교한 봇 | 거의 없음 (외부 의존 발생) |
| 전면 승인제 | 소 | 없음 | 전부 | 즉시 노출 안 됨, 운영 부담 |

**권장: 1~4번을 1차 구현에 포함.** 넷 다 사용자가 체감하지 못하고 구현이 가벼움.
Rate limit은 기존 방문자 봇 필터의 `ip_hash` 로직을 재사용하면 추가 비용이 거의 없음.
Turnstile은 실제 스팸이 들어온 뒤에 붙이고, 승인제는 응원글이 즉시 보이는 게
이 사이트 성격에 맞아 비추천.

> **이 프로젝트에 특히 중요한 오탐 시나리오**: 공연 관람 후 같은 장소(교회·공연장
> 와이파이)에서 여러 명이 동시에 응원글을 남기면 IP가 같아 rate limit에 걸림.
> 충분히 있을 법한 상황이므로 **IP당 시간당 제한을 넉넉히(10건 이상)** 잡거나
> IP+이름 조합으로 완화할 것.

**한계를 분명히 해두면**, 1~4번은 "쉬운 봇"만 막습니다. 표적형 스팸이 오면 뚫립니다.
다만 소규모 공연 사이트가 표적이 될 이유가 적고 대부분 무차별 크롤링 봇이므로
1차로는 충분하다는 판단입니다.

## 3. 시안에서 실제로 달라진 것

### 히어로 이미지 교체 — 규격은 그대로

`Rectangle 14`의 채우기가 `1.png`(노란 바탕 손글씨 포스터,
`창작뮤지컬 <나지르> 기록 및 후원 안내`)로 바뀌었습니다. 크기·위치·오버레이는 동일합니다.
코멘트 #4의 "임의로 첨부한 사진"에서 한 단계 진행된 상태이나, **최종본인지는 확인이 필요**합니다.

### 랜딩 카드 아이콘 교체 — ⚠️ 크기는 여전히 제각각

이미지가 `icon1.png` ~ `icon5.png`(손그림 스타일)로 교체됐습니다.
다만 **프레임 크기는 옛 값 그대로**입니다 — 실측 확인:

| 카드 | 아이콘 크기 |
|---|---|
| 1 `<나지르>에 대하여` | `181 × 160` |
| 2 `제작 과정` | `139 × 122` |
| 3 `함께하는 사람들` | `181 × 160` |
| 4 `후원과 기도` | `157 × 139` |
| 5 `응원 게시판` | `169 × 149` |

코멘트 #3의 "최종 아이콘 나오면 크기 통일" 요구는 **아직 미해결**입니다.
구현 시 한 값으로 통일하거나(예: `160 × 160` 박스에 `object-fit: contain`) 디자이너에게 정렬을 요청해야 합니다.

### `<나지르>에 대하여` 하위 제목 표기

| # | 문서 표기 | 시안 표기 |
|---|---|---|
| 02 | `PRAY SOUND` | **`Praysound에 대하여`** |
| 04 | `등장인물` | **`작품 속 인물`** |

작품 개요 카드 값도 채워졌습니다 — `Form 창작 뮤지컬` / `Produced Praysound` /
`Running time 약 2시간(인터미션 포함)` / `Date 2027년 2월 셋째 주 예정`.

⚠️ 01·02의 좌측 본문은 아직 `간단한 설명 간단한 설명…` 더미입니다(코멘트 #42).
`기도로 동참하기`의 기도 제목 6개는 실제 문구로 채워져 있습니다.

### GNB 메뉴 라벨 표기 불일치

GNB는 `나지르에 대하여`(꺾쇠 없음), 카드·페이지 제목은 `<나지르>에 대하여`입니다.
의도인지 확인 필요 — 코드에서는 한쪽으로 통일하는 편이 낫습니다.

활성 메뉴는 **노랑 + 밑줄**로 그려져 있습니다 → 코멘트 #26 "밑줄 간격 미정" 보류 해제 가능.

### 제작 과정 01 — `전체 일정 보기`

카드 2장(`지나온 이야기` 검정 / `앞으로 걸어갈 이야기` 노랑), 각 5개 항목 + 하단 `전체 일정 보기`.
명세서 24~25행("기본 약 5개 표시 → 전체 일정 보기로 전체 확인")과 정확히 맞습니다.

## 6. 요구사항 명세서 검토

시트 `최신 버전`, 48개 항목(2~49행). 대분류: 공통 / 랜딩 페이지 / `<나지르>`에 대하여 /
제작 과정 / 함께하는 사람들 / 후원과 기도 / 응원 게시판 / 관리자.

**화면에 보이는 것과 관리자 CRUD는 빠짐없이 적혀 있습니다.** 빠진 건 화면에 안 보이는 영역입니다.

### 6-1. 누락 — 명세에 아예 없는 것

1. **응원 게시판 스팸·봇 방어**
   로그인 없이 누구나 글을 쓰는 유일한 기능인데 레이트리밋·허니팟·링크 필터·비속어 처리가 없습니다.
   공연 홍보 사이트라 URL이 퍼지면 스팸이 바로 들어옵니다.
2. **응원 메시지 페이지네이션 / 더보기**
   시안은 8개를 보여주는데, 100개가 쌓였을 때 어떻게 되는지 정의가 없습니다.
3. **작성자 본인의 수정·삭제**
   삭제 권한이 관리자(46행)에만 있습니다. 잘못 쓴 사람이 지울 방법이 없습니다.
4. **쪽지의 좋아요/하트**
   시안 쪽지 좌하단에 아이콘이 있는데 명세에 대응 항목이 없습니다.
5. **반응형·모바일 요구사항 0건**
   48개 항목 어디에도 모바일 언급이 없습니다. 그런데 코멘트 #21·#30은 "휴대폰으로 볼 때"를
   전제로 한 요구입니다. Figma 모바일 시안도 랜딩 1장뿐입니다.
6. **SEO / OG 메타태그 / 공유 썸네일**
   후원을 받는 홍보 사이트라 카톡·인스타 공유 시 썸네일이 사실상 필수인데 항목이 없습니다.
7. **이미지 업로드 제약**
   구성원 이미지, 인사말 이미지, 등장인물 이미지가 전부 업로드형인데
   허용 포맷·최대 용량·리사이즈 규칙이 없습니다.
8. **관리자 로그인 보안**
   48행이 "지정된 관리자 계정으로 로그인"뿐입니다. 세션 유지 시간, 실패 횟수 제한,
   비밀번호 정책이 없습니다.
9. **개인정보 처리방침**
   응원 게시판에서 이름을 수집하고, 푸터에 실명·연락처를 노출합니다. 안내 페이지 항목이 없습니다.
10. **빈 상태 / 에러 처리**
    데이터 0건일 때 화면, 등록 실패 시 처리에 대한 정의가 없습니다.
11. **방문자 통계**
    이미 코드에 구현돼 있는(`VisitBeacon`) 기능인데 명세에 없습니다. 유지할지 확인 필요.

### 6-2. 애매해서 구현 전에 정해야 하는 것

- **8~11행 "세부 페이지 슬라이드"**
  좌우 슬라이드로 세부 페이지를 넘긴다고 돼 있는데, 이게 **URL이 바뀌는 라우트**인지
  **한 페이지 안의 슬라이드**인지가 안 정해져 있습니다.
  후자면 특정 세부 페이지 링크를 공유할 수 없고 SEO도 안 잡힙니다.
  → 라우트로 나누고 전환만 슬라이드 애니메이션으로 주는 방식을 권합니다.
- **14~16행 "연출의 인사말을 이미지 형태로 표시"**
  텍스트가 아니라 **이미지**입니다. 시안의 손편지도 이미지입니다.
  이러면 본문 검색·복사·스크린리더가 전부 안 됩니다. alt 텍스트 정책이 필요합니다.
- **7행 `페이지 정보 관리` vs 49행 `콘텐츠 관리`** — 범위가 겹칩니다.
- **중요도가 48개 중 46개가 '상'** 입니다. 사실상 우선순위 구분이 없는 상태입니다.

### 6-3. 명세 ↔ 시안 ↔ 코멘트가 다른 것

| 항목 | 명세서 | 시안 | 코멘트 |
|---|---|---|---|
| 함께하는 사람들 카드 | 32~34행 — **"이미지 표시"만.** 상세페이지 항목 없음 | 빈 노란 박스(사진·이름·역할 미정) | #37 "사진+역할+이름, 누르면 개인 페이지" |

현재 코드에는 이미 `/people/[id]` 상세 페이지가 있습니다. **명세대로 가면 이 라우트를 버려야 하고,
#37대로 가면 명세에 항목을 추가해야 합니다.** #46 답변으로 정리될 사안입니다.

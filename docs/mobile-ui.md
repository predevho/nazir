## ⚠️ 작업 전에 반드시 알아야 할 것

### 1. `use_figma`(MCP)로는 시안 폰트를 못 씁니다

빛의계승자체(`Heir of Light OTF`)와 그리운 고씨네는 **로컬 설치 폰트**라, MCP 실행 환경(Figma 클라우드 폰트 1,938종)에서 `loadFontAsync`가 실패합니다.

| 동작 | 가능 여부 |
|---|---|
| 새 텍스트 생성 / 글자 내용 수정 | ❌ |
| `fontSize` · `lineHeight` · `textAlignHorizontal` 변경 | ❌ |
| **기존 텍스트 노드 복제(clone)** | ✅ 폰트가 그대로 딸려옴 |
| 복제본의 `x`/`y` 이동 · `resize` · `fills` · `opacity` · `name` · `appendChild` | ✅ |

랜딩 모바일은 **전부 이 복제 방식**으로 만들었습니다. 그래서 글자 크기는 데스크톱 값 고정입니다
(GNB 20px · 카드 제목 25px · 부제 12px · 설명 10px · 푸터 제목 26px · 본문 15px).

**Figma 데스크톱 앱에서 사람이 직접 작업하면 이 제약이 전부 없습니다.**

### 2. Figma MCP 호출 한도 (Starter 플랜)

작업 도중 한도에 걸려 중단됐습니다. 한도가 남아 있을 때는 `use_figma` 스크립트가 압도적으로 빠르고 안전합니다.

### 3. 브라우저 자동화로 Figma를 조작하는 것은 위험합니다

한도 소진 후 Chrome 확장으로 이어서 작업했는데, 화면 좌표가 스크린샷마다 달라져(창 크기 1092↔1553↔720) **오조작이 4번** 났습니다.

| 사고 | 원인 |
|---|---|
| 캔버스에 `Line 25` 생성 | 더블클릭이 프레임 내부로 진입 → 이후 타이핑이 단축키로 해석 |
| 엉뚱한 텍스트가 노드로 붙음 | `Cmd+C`가 페이지 이동 직후엔 안 먹어 OS 클립보드의 다른 내용이 붙음 |
| 프레임 오복제 | 클립보드에 의도한 요소가 아니라 직전 프레임이 들어 있었음 |
| 자식 6개 불투명도 30% | 빗나간 클릭 뒤 "930" 입력이 불투명도 단축키로 해석 |

전부 복구했지만, **놓치면 원본 시안에 그대로 남습니다.** 숫자를 입력할 때 포커스가 캔버스에 있으면 그게 불투명도 단축키가 됩니다.

우클릭 메뉴의 `복사`는 클립보드에 제대로 안 들어갑니다. 신뢰할 수 있는 복사 경로는 **캔버스에 포커스가 있는 상태의 `Cmd+C`** 하나뿐입니다.

## 코드 쪽 모바일 대응 (2026-09-10)

시안 프레임과 별개로, 배포된 사이트가 휴대폰에서 제대로 동작하는지 12개 라우트를
375 / 390 / 768 / 1024 / 1440 다섯 폭에서 측정해 고쳤습니다.

### 확인 결과 이미 정상이던 것

- **가로 넘침** — 12개 라우트 전부 없음
- **`/people` 그리드** — 모바일 2열(157.5px)로 이미 재배치되어 있음
- **편지 이미지** — 원본 1268×1691이 컨테이너 비율 634:846과 일치해 잘리지 않음

### 고친 것

| 문제 | 조치 |
|---|---|
| 응원 폼이 390에서 한 줄 유지 → 메시지 칸이 167px | `sm` 미만에서 세로로 쌓음. 버튼도 전체 폭 `응원 남기기 ›` |
| 입력 글자 15px → iOS 사파리가 포커스 시 화면 확대 | 모바일 16px, 데스크톱은 시안값 15px 유지 |
| 도트·화살표 18px, 페이저·더보기·뒤로가기가 손끝보다 작음 | `.tap-target` 유틸(globals.css)로 **눌리는 범위만** 44px |
| 도트 4개 + 화살표가 390에서 344px → 콘텐츠 폭 327 초과 | 도트 간격을 모바일만 32px로. 데스크톱은 시안 60px 그대로 |
| 푸터 링크 높이 23px (WCAG AA 최소 24px 미달) | 모바일만 `py-1`로 31px. 데스크톱 시안 그대로 |

### `.tap-target` 을 쓰는 이유

요소 자체를 키우면 "도트 지름 18 · 간격 60" 같은 시안 수치가 전부 틀어집니다.
그래서 레이아웃에 영향이 없는 `::before` 가상 요소로 눌리는 범위만 넓혔습니다.
도트 중심 간 거리는 데스크톱 78px(=18+60)로 시안 그대로 유지됩니다.

**주의**: 세로로 촘촘히 쌓인 링크(푸터 등)에는 쓰지 마세요. 44px 범위가 서로 겹쳐
아래 링크가 위 링크의 터치를 가로챕니다. 그런 곳은 간격 자체를 벌리는 편이 맞습니다.

### 손대지 않은 것

- **랜딩 카드 설명 11px** — 모바일 시안이 명시한 값입니다. 폰트 잠금 때문에 데스크톱
  크기를 그대로 복제한 결과라는 단서가 있어(위 "작업 전에 반드시 알아야 할 것" 1번)
  디자이너 확인 후 조정하는 편이 안전합니다.
- **`/people/[id]` 개인 페이지 전체 레이아웃** — 이 화면만 옛 스타일(`font-mono`,
  `max-w-[820px]`)로 남아 있습니다. 시안이 없어 이번엔 뒤로가기 링크 크기만 맞췄습니다.

## 스와이프를 손가락에 붙이기 (2026-09-10)

처음 붙인 스와이프는 "일정 거리 이상 밀면 `router.push`"였다. 넘어가긴 하는데
미는 동안 화면이 가만히 있어서 넘기고 있다는 느낌이 없었다.

### 끌리는 동안 본문이 따라온다

`SwipeNavigator` 가 `touchmove` 마다 본문에 `translateX` 를 준다.

| 상황 | 동작 |
|---|---|
| 다음/이전이 있는 쪽으로 밀기 | 손가락 거리만큼 그대로 따라온다 |
| 끝 장에서 더 밀기 | 거리의 0.25배만 밀린다 — 끝이라는 것이 손끝에 전해진다 |
| 세로가 우세한 제스처 | 아예 따라오지 않는다. 스크롤에 양보한다 |
| 충분히 밀고 놓기 | 남은 거리를 마저 밀어내고 이동한다 |
| 덜 밀고 놓기 | 제자리로 돌아온다 |

방향은 첫 8px 로 한 번 정하고 그 제스처 동안 바꾸지 않는다. 중간에 판정이 뒤집히면
본문이 붙었다 떨어졌다 한다.

### 새 화면은 반대쪽에서 들어온다

넘긴 방향을 `SwipeNavigator` 모듈 변수(`cameFrom`)에 담아 다음 화면이 읽는다.
클라이언트 이동이라 모듈이 살아 있어서 넘어간다. 들어오는 쪽은 WAAPI(`element.animate`)로
`translateX(±100%) → 0` 을 260ms 재생한다.

`prefers-reduced-motion: reduce` 면 애니메이션을 통째로 건너뛴다. 이동은 그대로 된다.

### 코치마크 — 처음 온 사람에게 한 번만

스와이프는 화면에 흔적을 남기지 않아 알려주지 않으면 있는 줄도 모른다.
`SwipeHint` 가 하단에 `‹ 왼쪽으로 밀어 다음 장으로` 알약을 띄운다.

띄우는 조건은 넷을 모두 만족할 때다.

- 다음 장이 있을 것 (마지막 장에는 뜨지 않는다)
- `(pointer: coarse)` — 손가락 기기. 좁은 데스크톱 창에는 스와이프가 없다
- `md` 미만 (CSS `md:hidden`)
- 이 기기에서 아직 본 적 없을 것 (`localStorage: nazir:swipe-hint-seen`)

사라지는 경우는 셋이다. 가로로 밀기 시작할 때 / 눌렀을 때 / 6초 뒤 저절로.
어느 쪽이든 `localStorage` 에 표시해 다시 뜨지 않는다.

### 확인하지 못한 것

미리보기 패널에서 `requestAnimationFrame`·scroll·IntersectionObserver·CSS 전환이
모두 발화하지 않는다. 그래서 **애니메이션이 실제로 어떻게 보이는지는 확인하지 못했다.**
확인한 것은 값과 상태뿐이다 — 끌리는 중 `translateX(-130px)`, 놓은 뒤 주소 이동과
`transform` 초기화, 코치마크의 표시·해제 조건.
